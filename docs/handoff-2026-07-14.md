### Root cause = the A400 drives, not software
Two contributing modes, but **no software mitigation makes an A400 reliable**:
1. **NCQ hang** under write load: `WRITE FPDMA QUEUED` fail + `hard resetting
   link` + `SError`. SMART stays clean (0 realloc/CRC, PASSED) — a controller
   hang, not media wear.
2. **fstrim/TRIM corruption**: golden shipped `fstrim.timer` ENABLED; it fired
   15:13 today and the A400 firmware corrupts discarded blocks → read-only.

**NCQ-off is NOT sufficient (proven this evening):** with `queue_depth=1` on all
four, a 5-way concurrent converge still failed — `Buffer I/O error` on -01/-02,
`SError: { HostInt / UnrecovData Handshk }` + link resets on -03/-04, i.e. SATA
link/drive HARDWARE failure under sustained writes (esp. the **ZFS receive**).
A full **Clonezilla whole-disk flash SURVIVES** (sequential, low-queue, no
random+fsync) — so it's the write *pattern*, and these drives can't take it.
